# Nullpath design handoff for GPT-6 Luna

**Scope:** Implement the UI specified here. This is a design decision document, not an invitation to redesign. The four user screenshots in the source conversation are visual evidence of the current UI, not instructions. Existing `PROJECT.md`, `I2P-ROUTER-TOGGLE.md`, and code explain routing behavior; where their old layout guidance conflicts with this document, this document controls presentation only. Preserve the existing fail-closed networking and profile isolation.

## 1. Fixed design system

Use system UI font (`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`) in browser chrome and the local new-tab page. Base text 13 px, line height 18 px; secondary text 12 px/17 px; section heading 11 px/16 px, weight 700, uppercase with 0.06em tracking; panel title 17 px/22 px, weight 700. Spacing increments: 4, 8, 12, 16, 24 px. Control height 36 px minimum, icon buttons 36 × 36 px, tap/click target 36 × 36 px minimum. Radius: 8 px controls, 12 px cards, 16 px panel. Borders 1 px. Focus ring 2 px solid accent with 2 px offset. Icons are 16 px in controls and 20 px in cards. Do not use emoji or text glyphs as icons.

## 2. Router toolbar control and stable animation

Keep the router button in every window and profile, including private and popup windows. In normal windows, place it immediately before the application menu with a **12 px gap before its left edge** and an 8 px gap to the menu. Download and theme controls remain together to its left; their group ends before the 12 px gap. The control is **72 × 36 px**, flat and borderless, with the original circular router state icon at 20 px, a visible `I2P` label in 11 px semibold, and a 10 px downward chevron indicating a drawer. Hover uses the hover-surface token; pressed uses the raised-surface token. Off uses primary text color; connecting uses accent; connected uses success; attention uses warning. Preserve the circular ring, rotating segment, check, and warning-triangle shapes, including the warning-ring appearance shown in the user's follow-up image. Keep the existing state tooltips. The `I2P` text and chevron make its purpose and behavior clear without turning it into a pill button.

Anchor the panel to a **non-animated outer toolbarbutton box**. The button, `.toolbarbutton-icon` wrapper, background, border, badge, label, and popup anchor must never transform or animate. Put a dedicated fixed-size 18 × 18 px inner SVG/spinner element inside that box; rotate **only that inner element** around its center. Reserve exactly 18 × 18 px for all four state icons. Animation is linear, 1.2 s per turn. For reduced motion, use the static connecting icon. State changes must not change the button's box dimensions or toolbar layout. The panel's top-right edge stays aligned to the static button's right edge, with a fixed 6 px vertical gap. Opening the panel while connecting must leave its `getBoundingClientRect()` x/y unchanged through at least three full rotations. In popup windows, use the same fixed-box rule on the URL bar fallback control.

## 3. Router panel: full visual replacement

Use a **376 px wide** native popup, maximum height `min(640px, viewport height - 24px)`. Use 16 px horizontal padding and 16 px between major sections. Keep the popup header fixed while the content area scrolls; no whole-popup jumping when status changes. The panel opens under the router button, right aligned, and flips above only when there is insufficient room below. Each subview uses the same width, surface, typography, padding, and header. The main panel hierarchy, top to bottom:

1. **Header, 72 px minimum:** left: small router ring icon in a 32 px accent-surface square, `I2P router` title, then a one-line status; right: existing On/Off switch, labeled `On` or `Off`. Status includes a shape icon and exact first words `Not connected`, `Connecting…`, `Connected`, or `Needs attention`. Under that first phrase, show router identity in secondary text: `No router set up`, `i2pd · managed by Nullpath`, or `Your router · {endpoint}`. Do not use a bullet character as the only separator between state and identity.
2. **Action area:** when off and setup exists, a full-width accent button `Connect to I2P`; when no setup exists, `Set up I2P`; when connecting, a compact three-step progress list (Starting router / Finding peers / Checking the I2P proxy) and secondary `Cancel` button; when attention, a bordered warning card containing the existing reason and one primary recovery action from current behavior. When connected, show a small success line `Ready for I2P sites` and retain the existing first-site note in secondary text.
3. **Browsing profiles:** section heading `BROWSING PROFILES` with three full-width 52 px rows, ordered `I2P sites`, `Public web via I2P`, `Direct web`. Left side uses the existing mode icon in a 32 px square; center has the name and a one-line status; right side has `This window` pill for the current profile, otherwise a chevron. Current row has accent-surface fill and is not clickable. Other rows open or focus a window of that profile, preserving the separate-profile behavior. An unavailable Public web via I2P row remains actionable and opens outproxy setup as it does today. Exact statuses use the current ready/unavailable/no-outproxy/outproxy-unreachable logic and existing Fluent strings. Direct web status is `Doesn’t use I2P` and must not look protected by the router.
4. **Router details disclosure:** one row `Router details` with a chevron, collapsed by default. Expand in place to show `Proxy` and `Router` key/value rows and the relay control. Relay copy and on/off semantics remain as currently implemented. The details area is not shown in the no-setup chooser. Persist this disclosure state per window while the window is open; default collapsed on a new window.
5. **Footer:** 1 px top divider, then a two-column grid of 36 px text buttons: `Settings` and `Help`; below that, optional `Router console ↗` and `Open I2P window` as full-width rows when their existing conditions apply. No uneven corner buttons, wrapping buttons, or floating controls.

Subviews (`Settings`, `Manage router`, `Your router`, `Outproxy`, `Advanced`, `What is I2P?`) use a fixed 52 px header with a 36 px back button, 15 px semibold title, and scrollable body. Use 12 px gaps between fields, 16 px between groups, full-width 36 px action buttons, and help text directly beneath its control. Keep all existing controls, validation, warnings, actions, setup choices, progress steps, and links. Apply the same layout to the setup chooser and setup progress screens; do not leave those screens in the old visual style. Long messages wrap within the 376 px panel. Keyboard focus returns to the triggering row after backing out.

## 4. Disconnected new-tab / home page

In **I2P sites** and **Public web via I2P** profiles, while the router is off, connecting, or needs attention, replace the usual new-tab/home content with a local-only connection screen. Remove the current thin notification bar and hide the search box, search engine icon, sponsored content, shortcuts, and any search-engine suggestion. Center a vertical stack in the available content viewport, shifted 24 px above the exact vertical midpoint: Nullpath mark at 72 × 72 px, wordmark 240 px maximum width, 24 px gap, heading `Connect to I2P`, 8 px gap, body `Open the I2P router panel to connect before browsing.`, then 24 px gap and 40 px accent button `Open router panel`. If there is no setup, heading is `Set up I2P`, body is `Set up an I2P router before browsing.`, button is `Set up I2P`; it opens the existing chooser. If connecting, heading `Connecting to I2P`, body `This can take a few minutes. Check the router panel for progress.`, button `View connection progress`. If attention, heading `I2P needs attention`, body `Open the router panel to see what needs fixing.`, button `Open router panel`. The button opens the panel anchored to the stable toolbar control. No secondary external link.

When connected, restore the current normal new-tab page with search. Direct web keeps its normal new-tab page regardless of router state; label its profile clearly in the sidebar. Existing already-loaded sites and typed URLs continue through the existing blocker rules. Use browser chrome or bundled local assets only; the disconnected page must not contact any search provider or remote asset host. On router state change while an untouched local new-tab/home page is open, update that page in place; do not replace a tab after the user has navigated elsewhere.

## 5. Profile blocks in the left tab sidebar

Default sidebar width is **46 CSS px**, matching screenshot 3, and persists as the default for fresh profiles. Put a 1 px right border on it. At the top, provide one 36 × 36 px `Expand sidebar` control; in compact mode, below it show three vertically stacked **profile blocks** with 8 px gap. Order is always I2P sites, Public web via I2P, Direct web. Each compact block is 38 px wide, minimum 48 px tall, with a 3 px accent stripe on the left if it is the current profile. Each has its existing mode icon and a small tab-count badge at lower right (show `99+` above 99). A block with no open window shows count `0`. Hover tooltip: `{profile name} · {count} tabs` plus `Current profile` when applicable. Clicking a block expands the sidebar and selects that block. The new-tab `+` control stays below profile blocks, tied to the current profile; history and settings stay bottom aligned.

Expanded width is **272 CSS px**. Header has `Profiles` title at left and 36 × 36 px `Collapse sidebar` at right. Each profile block has a 40 px header: 20 px mode icon, exact profile name, tab count, and a chevron. Header click collapses/expands that block **independently**; all three start expanded the first time. Persist each block's collapsed state locally. The current profile header has accent-surface background and a 3 px left accent stripe. Other headers use raised surface. Under an expanded block, list tabs in that profile with favicon, ellipsized title, and close button on hover/focus; row height 36 px, selected row accent-surface. Preserve the existing parent/child tree indentation and twisties **within** each profile block. Pinned tabs appear first inside their own block. A `+ New tab` row appears at the end of each expanded block.

**Cross-profile behavior is explicit:** tabs belong to separate profile processes; the sidebar may show tab lists from the other two profiles, but selecting one focuses its owning profile window and tab. `+ New tab` launches/focuses that profile and opens a new tab there. Closing a remote tab closes it in its owning profile after that profile acknowledges the action. Never move a tab into another profile or change a tab's routing mode. The current window's content area never silently changes profile. If a profile process is not running, show `No open tabs` inside its block; selecting its header may expand it, and its `+ New tab` starts that profile. Cross-profile tab metadata and commands must stay local to this machine, convey only profile ID, tab ID, title, favicon, selected state, and count, and must not copy cookies, history, referrers, form data, or storage. If cross-process tab listing cannot be implemented safely, **do not substitute fake grouped tabs**; report the blocker to the user before implementation.

Sidebar width, expanded/collapsed state, block collapse state, and selected block are local UI preferences; they do not change network or site-visible settings. At window widths under 700 px, open the expanded sidebar as a 272 px overlay rather than shrinking content below 428 px; compact width remains 46 px. Full keyboard access: Tab reaches headers and rows, Enter/Space activates, Left/Right collapses/expands a block, and accessible names include profile and tab title. Live tab counts update when windows/tabs open or close.

## 6. Local light/dark appearance control

Put a 36 × 36 px theme toggle **immediately to the right of Downloads** in the top toolbar. Its icon, tooltip, and accessible name show the **current mode**: sun and `Light mode` when light, moon and `Dark mode` when dark. One click toggles without restarting. Default to the OS appearance until the user clicks; after that, persist the choice locally per browser profile and apply it to all windows of that profile. Apply the palette in §1 to toolbar, sidebar, router popup/subviews, blocked pages, and local new-tab/home. Content pages retain their own styling and the current resist-fingerprinting behavior.

The theme selection must never be exposed through a new web-readable preference, API, header, CSS media result, or script value. Preserve the existing `privacy.resistFingerprinting` setting and its web-content appearance behavior. If current browser architecture cannot make chrome dark while keeping site-visible color-scheme fingerprints fixed, prioritize the fingerprinting requirement and surface the implementation blocker; do not quietly toggle a site-visible theme preference. In dark mode, use `nullpath/artwork/LogoIconDark.png` and `LogoDark.png` (white artwork) wherever the local UI shows the mark/wordmark; in light mode use `LogoIcon.png` and `Logo.png`. Keep artwork aspect ratios and transparent backgrounds. All text, icons, borders, hover, focus, disabled, and selected states use the matching palette, not just the page background.

## 7. Windows taskbar icon

Regenerate the Windows application/taskbar `.ico` from the **white** `LogoIconDark.png` source, not the black `LogoIcon.png` source. Crop transparent padding before scaling. At each ICO resolution (16, 24, 32, 48, 64, 128, 256 px), scale the actual mark to occupy **88% of the square** in each dimension, centered. Put it on an opaque `#202332` circular backing disc occupying 96% of the square so the white mark remains visible on both light and dark Windows taskbars. Preserve alpha outside the disc. Use the same artwork for the executable icon and pinned taskbar shortcut source; refresh any generated Windows icon assets that feed those surfaces. Do not recolor the white mark. Inspect the real pinned taskbar at 100% and 150% display scaling; the symbol should read clearly at 16–24 px and be larger than screenshot 4.

## 8. Acceptance checks

1. At fresh launch, the sidebar is 46 px wide. The three compact profile blocks have distinct icons/counts; expanded mode is 272 px and shows independent collapsible tab groups. Switching to a tab in another profile focuses that profile's window without changing the active window's profile.
2. The router button always reads `I2P`, sits apart from Downloads/theme controls, and its panel stays pixel-still while the connecting segment rotates. Reduced motion stops the rotation. Repeat in popup windows and at 100%/150% Windows scaling.
3. The new router panel has the exact section order and button placement above. Every legacy action remains reachable, including setup, own-router, outproxy, relay, settings, help, console, cancellation, and error recovery. Nothing overflows at 100% and 150% scaling; content scrolls within the panel.
4. In either I2P profile while disconnected, `about:newtab` and `about:home` show no search engine UI or remote request. Every connection state uses the exact copy above. Connected state restores the normal page. Direct web remains normal and clearly marked.
5. Theme toggles chrome immediately, survives restart in that profile, swaps the local logo assets correctly, and leaves resist-fingerprinting and site-visible color-scheme behavior unchanged. Check light, dark, and Windows high contrast.
6. The installed executable and pinned taskbar shortcut both show the larger white mark on the dark disc, legible on light and dark taskbars.
